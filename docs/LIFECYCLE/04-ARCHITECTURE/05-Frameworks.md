# Frameworks

The Architecture stage is supported by internationally recognised enterprise architecture frameworks, standards, modelling languages, and governance practices that enable organisations to develop consistent, reusable, and governable enterprise architectures.

Within ENAF, these frameworks are not applied independently. Instead, they are integrated into a single lifecycle that transforms the approved Target State into detailed enterprise architecture, reference architectures, standards, and design guidance.

The Architecture stage focuses on defining **how the future architecture should be designed and governed**, providing the foundation for solution architecture and implementation.

---

# Purpose

The purpose of these frameworks is to provide proven methods for developing enterprise architecture that:

- Supports business strategy.
- Implements the approved Target State.
- Promotes architectural consistency.
- Enables technology standardisation.
- Supports enterprise governance.
- Reduces implementation risk.
- Encourages architectural reuse.

## ArchiMate®

### Purpose

ArchiMate provides the modelling language used to describe enterprise architecture consistently across all architecture domains.

Typical models include:

- Business Architecture Views
- Application Interaction Views
- Data Relationship Models
- Technology Architecture Views
- Infrastructure Models
- Security Architecture Views
- Cross-domain Architecture Views

ArchiMate enables consistent communication between architects, engineers, and business stakeholders.

## Enterprise Architecture Principles

### Purpose

Architecture principles provide the rules that govern future architectural and technology decisions.

Typical principles include:

- Business First
- Standardise Before Customise
- Cloud First
- Security by Design
- Automation by Default
- API First
- Reuse Before Build
- Design for Resilience
- Operational Simplicity

These principles ensure consistency across all future solution designs.

---

## Reference Architecture

### Purpose

- Cloud Reference Architecture

- Integration Reference Architecture
- Data Platform Reference Architecture
- Digital Workplace Reference Architecture

Reference architectures reduce design effort while improving architectural consistency.

# Framework Selection

Not every organisation requires every framework.

The Enterprise Architect should select the frameworks that best support:

- Business strategy.
- Organisational maturity.
- Industry sector.
- Regulatory obligations.
- Technology landscape.
- Enterprise architecture maturity.

ENAF provides the lifecycle within which these frameworks are applied consistently.

---

# Summary

The Architecture stage integrates proven enterprise architecture frameworks, modelling standards, governance practices, and technology standards to develop a governed enterprise architecture that supports consistent solution design across the organisation.

Rather than replacing established industry frameworks, ENAF combines them into a single lifecycle that transforms the approved Target State into reusable enterprise architecture, reference architectures, standards, and design guidance that support future transformation.
