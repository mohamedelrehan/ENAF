# Purpose

The purpose of the Target State stage is to answer one fundamental question:

> **Where do we want to be?**

Following completion of the Current State assessment, Enterprise Architects design the future enterprise that will enable the organization's strategic vision.

Before developing detailed architectures, implementation plans, or transformation roadmaps, the organization must establish a clear picture of its desired future state.

The Target State stage defines the future business and technology landscape by describing the capabilities, operating model, services, information, applications, infrastructure, security, and governance required to achieve the organization's long-term objectives.

Rather than designing individual technical solutions, this stage creates a shared enterprise vision that aligns business and technology around a common destination.

The Target State becomes the architectural blueprint that guides every design, investment, and transformation decision throughout the remainder of the ENAF lifecycle.

---

# Why This Stage Matters

Many transformation programmes fail because organisations begin implementing technology before defining the future enterprise they are trying to create.

Without a clearly defined Target State, projects often become isolated initiatives that optimise individual systems instead of transforming the organisation as a whole.

A well-defined Target State enables organisations to:

- Align business and technology around a common vision.
- Design future business capabilities before selecting technologies.
- Eliminate duplicated or conflicting transformation initiatives.
- Reduce architectural complexity.
- Prioritise investment based on business value.
- Improve decision-making across transformation programmes.
- Establish measurable transformation outcomes.
- Create a consistent direction for all architecture domains.

The objective of the Target State stage is not to produce detailed technical designs.

Instead, it defines the future enterprise that the organisation intends to become, providing clear architectural direction before implementation begins.

---

# Enterprise Design Domains

ENAF introduces **Enterprise Design Domains** to ensure the future enterprise is designed holistically rather than as a collection of independent technology projects.

Each domain contributes to a single integrated Target State Architecture.

| Enterprise Design Domain | Purpose |
|--------------------------|---------|
| Business | Define future business capabilities, value streams, and organisational outcomes. |
| Applications | Define the future application landscape and business services. |
| Infrastructure | Design the future compute, storage, and platform capabilities. |
| Network | Define secure, resilient, and scalable enterprise connectivity. |
| Cloud | Establish the future cloud operating model and platform strategy. |
| Security | Design security architecture based on enterprise risk and Zero Trust principles. |
| Operations | Define the future operational model, support processes, and service management capabilities. |
| Governance | Establish the governance model required to sustain the future architecture. |

Together, these domains provide a complete enterprise view of the desired future state and establish the foundation for all subsequent architectural work.

# What This Stage Answers

The Target State stage provides clear answers to questions such as:

| Question | Outcome |
|----------|---------|
| What should the future enterprise look like? | Defines the desired operating model and business capabilities. |
| Which capabilities must be introduced or modernised? | Identifies future business and technology capabilities. |
| Which existing capabilities should be retained? | Preserves investments that continue to deliver value. |
| Which technologies should be transformed or retired? | Simplifies the future technology landscape. |
| How should business services be delivered? | Defines future service architecture and operating principles. |
| How should cloud, infrastructure, and networks evolve? | Establishes the future technology platform. |
| How should security be embedded? | Defines future security architecture and governance. |
| How will success be measured? | Establishes measurable transformation outcomes. |

These answers provide the strategic direction for every architecture and delivery decision that follows.

---

# Expected Outcome

By completing the Target State stage, the Enterprise Architecture team produces a shared vision of the future enterprise.

The Target State defines:

- Future business capabilities.
- Target operating model.
- Enterprise architecture principles.
- Future application landscape.
- Future infrastructure and cloud platforms.
- Future network architecture.
- Future security architecture.
- Operational and governance model.
- High-level transition objectives.
- Strategic design principles.

The result is a validated Target State Architecture that provides a common destination for business leaders, architects, programme managers, and delivery teams.

---

# Relationship to the ENAF Lifecycle

The Target State stage builds directly upon the Strategy and Current State stages.

Each stage of the ENAF lifecycle answers one fundamental question.

| Lifecycle Stage | Primary Question |
|-----------------|------------------|
| Strategy | **Why are we transforming?** |
| Current State | **Where are we today?** |
| Target State | **Where do we want to be?** |
| Architecture | **What should we build?** |
| Roadmap | **When and in what order should we deliver it?** |
| Implementation | **How do we build it?** |
| Operations | **How do we operate it?** |
| Governance | **How do we control it?** |
| Optimization | **How do we continuously improve it?** |

This progression ensures every architectural decision remains traceable from business strategy through to operational excellence.

---

# Summary

The Target State stage transforms strategic ambition into a clearly defined architectural vision.

By answering the question **"Where do we want to be?"**, Enterprise Architects design the future enterprise across all Enterprise Design Domains, ensuring business strategy, technology, security, operations, and governance evolve together.

This future-state architecture becomes the foundation for detailed solution architecture, transformation roadmaps, implementation planning, and long-term enterprise evolution.

A successful transformation begins not by selecting technologies, but by designing the future enterprise the organisation intends to become.
