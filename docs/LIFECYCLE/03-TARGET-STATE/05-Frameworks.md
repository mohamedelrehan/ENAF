# Frameworks

The Target State stage is supported by internationally recognised enterprise architecture frameworks, industry standards, and best practices that guide the design of a future-state enterprise architecture.

Within ENAF, these frameworks are not used independently. Instead, they are integrated into a single lifecycle to ensure that the future architecture remains aligned with business strategy, governance requirements, and industry standards.

The Target State stage focuses on defining **what the future enterprise should become**, rather than **how it will be implemented**. The implementation approach is developed during the Roadmap and Implementation stages.

---

# Purpose

The purpose of these frameworks is to provide proven methods for designing a future-state enterprise architecture that:

- Supports business strategy.
- Addresses the findings of the Current State Assessment.
- Establishes a consistent architectural vision.
- Enables future transformation planning.
- Aligns with enterprise governance principles.

# Primary Frameworks

## TOGAF®

### Purpose

TOGAF provides the primary architectural methodology for designing the future-state enterprise architecture.

Within the Target State stage it supports:

- Business Architecture
- Application Architecture
- Data Architecture
- Technology Architecture
- Architecture Principles
- Target Architecture Definition

### ENAF Alignment

| TOGAF Concept | ENAF Target State Activity |
|--------------|----------------------------|
| Business Architecture | Future Business Architecture |
| Application Architecture | Future Application Architecture |
| Data Architecture | Future Data Architecture |
| Technology Architecture | Future Technology Architecture |
| Architecture Principles | Target State Principles |
| Target Architecture | Complete Target State |

## ArchiMate®

### Purpose

ArchiMate provides a standard modelling language for describing the relationships between business capabilities, applications, technology platforms, services, and infrastructure.

It helps visualise the Target State architecture using a consistent notation.

### ENAF Alignment

Typical models include:

- Business Capability Maps
- Business Process Models
- Application Interaction Diagrams
- Technology Architecture Views
- Infrastructure Models
- Cross-domain Dependency Views

---

## Business Capability Mapping

### Purpose

Business Capability Mapping ensures that the future architecture is driven by business capabilities rather than technology products.

Typical outputs include:

- Capability Maps
- Capability Heat Maps
- Future Capability Models
- Capability Prioritisation

---

## Business Process Management (BPM)

### Purpose

Business Process Management supports the design and optimisation of future business processes.

Typical techniques include:

- Process Modelling
- Value Stream Analysis

- Operating Model Design

## Cloud Adoption Frameworks

Cloud Adoption Frameworks help organisations define the future cloud operating model and supporting architecture.

Within ENAF these frameworks support:

- Cloud Strategy
- Landing Zone Design
- Platform Standardisation
- Cloud Governance

---

## Zero Trust Architecture

### Purpose

Zero Trust principles define how security should be incorporated into the future enterprise architecture.

Typical guidance includes:

- Identity-first Security
- Least Privilege Access
- Continuous Verification
- Network Segmentation
- Secure Remote Access
- Policy-based Access Control

Common reference models include:

- NIST Zero Trust Architecture
- Microsoft Zero Trust
- CISA Zero Trust Maturity Model

---

## Security Frameworks

Security frameworks provide the governance and control objectives required for the future security architecture.

Typical references include:

- NIST Cybersecurity Framework (CSF)
- ISO/IEC 27001
- CIS Critical Security Controls

These frameworks support:

- Security Governance
- Risk Reduction
- Compliance
- Security Architecture
- Resilience

---

## IT Service Management

# Governance Frameworks

The future architecture should align with organisational governance frameworks.

Examples include:

- COBIT®
- ISO 38500
- Enterprise Governance Policies
- Internal Architecture Standards

These frameworks ensure that:

- Architecture decisions are governed.
- Investments remain aligned with business objectives.
- Compliance obligations are maintained.
- Architectural standards are consistently applied.

---

# Compliance Frameworks

The Target State should consider applicable legal, regulatory, and industry obligations.

Examples include:

- GDPR
- NIS2
- DORA
- PCI DSS
- ISO/IEC 27001
- Industry-specific regulations

Compliance requirements should influence the future architecture rather than being added after implementation.

# Framework Selection

Not every organisation requires every framework.

The Enterprise Architect should select the frameworks that best support:

- Business objectives.
- Industry sector.
- Organisational maturity.
- Regulatory obligations.
- Transformation complexity.
- Technology strategy.

ENAF provides the lifecycle structure into which these frameworks are applied.

---

# Summary

The Target State stage combines proven enterprise architecture frameworks, governance models, security standards, cloud adoption guidance, and business architecture practices to define a future-state enterprise architecture that is aligned with business strategy and ready for governance review.

Rather than replacing existing industry frameworks, ENAF integrates them into a single, traceable lifecycle that provides consistency from business strategy through architectural design and subsequent implementation.
