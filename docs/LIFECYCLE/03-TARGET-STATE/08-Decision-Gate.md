# Decision Gate

The Target State Decision Gate (**TS-DG-01**) is the formal governance checkpoint that concludes the Target State stage of the ENAF lifecycle.

Its purpose is to verify that the proposed future-state enterprise architecture has been completed, reviewed, and approved before progressing to the Architecture stage.

The Decision Gate ensures that the future architecture is aligned with the approved business strategy, addresses the findings of the Current State Assessment, and provides a complete architectural vision that can be used as the foundation for detailed architecture design.

No work should begin in the Architecture stage until the Target State Decision Gate has been successfully approved.

---

# Purpose

The purpose of **TS-DG-01** is to:

- Verify that all Target State activities have been completed.
- Confirm that all required Target State deliverables have been produced.
- Validate alignment with the approved Strategy and Current State outputs.
- Confirm stakeholder agreement with the future architecture.
- Ensure the Target State is ready to become the approved architectural baseline.
- Authorise progression to the Architecture stage.

---

# Review Criteria

The Decision Gate should confirm that:

- The future architecture supports the approved business objectives.
- The Current State findings have been addressed.
- The future architecture is internally consistent.
- Architectural principles have been defined.
- Stakeholders have reviewed the proposed Target State.
- Assumptions and constraints have been documented.
- Compliance requirements have been considered.
- Governance requirements have been satisfied.
- The architecture is suitable to progress to detailed architecture design.

---

# Decision Outcomes

The governance board should record one of the following outcomes.

| Decision | Description |
|----------|-------------|
| **Approved** | The Target State is approved and the Architecture stage may begin. |
| **Approved with Conditions** | Minor actions remain. The Architecture stage may begin once the agreed conditions have been satisfied. |
| **Deferred** | Additional information or clarification is required before a decision can be made. |
| **Rejected** | Significant issues have been identified. The Target State stage must be revisited before resubmission. |

---

# Participants

The Decision Gate should include representatives appropriate to the organisation, typically including:

- Executive Sponsor
- Enterprise Architect
- Business Leadership
- Domain Architects
- Security Representatives
- Technology Leadership
- Governance or Architecture Review Board

---

# Approved Outputs

Following successful approval through **TS-DG-01**, the Target State deliverables become the official approved outputs of the Target State stage.

| Output ID | Approved Output |
|-----------|-----------------|
| TS-OUT-01 | Approved Future Business Architecture |
| TS-OUT-02 | Approved Future Application Architecture |
| TS-OUT-03 | Approved Future Data Architecture |
| TS-OUT-04 | Approved Future Technology Architecture |
| TS-OUT-05 | Approved Future Security Architecture |
| TS-OUT-06 | Approved Future Network Architecture |
| TS-OUT-07 | Approved Target State Principles |
| TS-OUT-08 | Approved Future Architecture Vision |
| TS-OUT-09 | Approved Target State Summary |

These approved outputs become the mandatory inputs for the Architecture stage.

---

# Governance Responsibilities

The Enterprise Architect is responsible for:

- Presenting the completed Target State deliverables.
- Demonstrating alignment with Strategy and Current State outputs.
- Explaining key architectural decisions.
- Documenting assumptions and constraints.
- Recording any agreed actions resulting from the Decision Gate.

The governance board is responsible for approving, deferring, or rejecting the proposed Target State.

---

# Summary

The Target State Decision Gate (**TS-DG-01**) provides formal governance approval for the organisation's future-state enterprise architecture.

Following successful approval, the Target State deliverables become approved architectural outputs and establish the authorised future-state baseline for the Architecture stage.
