# Frameworks

## Purpose

The Implementation stage does not prescribe a single delivery methodology.

Every organisation has its own delivery model, governance structure, and preferred project management practices. Some organisations operate using traditional waterfall delivery, while others adopt Agile, hybrid, or scaled Agile approaches.

The purpose of this stage is to ensure that regardless of the chosen methodology, all programmes, projects, and delivery teams remain aligned with the approved Enterprise Strategy, Enterprise Architecture, Roadmap, governance model, and business objectives.

ENAF provides the governance framework that connects enterprise planning with transformation delivery.

---

# Framework Principles

The Implementation stage is based on the following principles.

## Business-Driven Delivery

Transformation programmes should always be driven by business objectives rather than technology alone.

## Architecture-Led Implementation

All projects should align with the approved Enterprise Architecture, architecture principles, and technology standards.

## Governance Throughout Delivery

Governance is maintained throughout the implementation lifecycle, ensuring transparency, accountability, and informed decision-making.

## Incremental Value Delivery

Business capabilities should be delivered in manageable increments that provide measurable value throughout the transformation programme.

## Methodology Independence

ENAF complements existing delivery methodologies rather than replacing them.

# Programme Management Frameworks

Programme management coordinates multiple related projects to achieve strategic business outcomes.

Typical frameworks include:

| Framework | Typical Use |
|----------|-------------|
| MSP (Managing Successful Programmes) | Enterprise transformation programmes |
| PMI Standard for Program Management | Programme governance and portfolio management |
| Organisation-specific Programme Management Office (PMO) | Internal programme governance |

These frameworks help organisations coordinate:

- Programme governance
- Business outcomes
- Benefits realisation
- Resource management
- Executive reporting
- Cross-project dependencies

---

# Project Management Frameworks

Projects deliver specific business capabilities within a transformation programme.

Typical frameworks include:

| Framework | Typical Use |
|----------|-------------|
| PRINCE2 | Controlled project delivery |
| PMBOK (PMI) | Project management best practices |
| Hybrid Project Delivery | Combined Agile and traditional approaches |

These frameworks support:

- Project planning
- Scope management
- Cost management
- Schedule management
- Risk management
- Stakeholder management
- Project governance

---

# Agile Delivery Frameworks

Agile delivery enables teams to deliver value through iterative development and continuous improvement.

Typical frameworks include:

| Framework | Typical Use |
|----------|-------------|
| Scrum | Team-based iterative delivery |
| Kanban | Continuous workflow management |
| SAFe | Enterprise-scale Agile delivery |
| Lean | Continuous value improvement |

Agile practices commonly include:

- Product backlogs
- Sprint planning
- Daily stand-ups
- Sprint reviews
- Retrospectives
- Continuous improvement

ENAF supports Agile delivery while ensuring enterprise governance and architectural alignment are maintained.

---

# Enterprise Architecture Frameworks

Implementation should remain aligned with the approved Enterprise Architecture throughout programme and project delivery.

Common frameworks include:

| Framework | Purpose |
|----------|---------|
| TOGAF | Enterprise Architecture governance |
| Zachman Framework | Enterprise classification |
| ArchiMate | Architecture modelling |

These frameworks help ensure:

- Architectural consistency
- Design governance
- Technology standardisation
- Solution traceability

---

# Governance Frameworks

Implementation should operate within an established governance model.

Examples include:

| Framework | Purpose |
|----------|---------|
| COBIT | Enterprise governance |
| ISO/IEC 38500 | Governance of IT |
| Internal Governance Boards | Organisational decision-making |

Governance activities include:

- Architecture reviews
- Stage approvals
- Risk management
- Policy compliance
- Executive oversight

---

# Service Management Frameworks

As implementation progresses towards operational handover, service management practices become increasingly important.

Common frameworks include:

| Framework | Purpose |
|----------|---------|
| ITIL | IT service management |
| ISO/IEC 20000 | Service management standard |

These frameworks support:

- Service transition
- Operational readiness
- Incident management
- Change enablement
- Service improvement

---

# DevOps and Automation Practices

Modern transformation programmes increasingly adopt automation to improve delivery speed, quality, and consistency.

Typical practices include:

- Infrastructure as Code (IaC)
- Continuous Integration (CI)
- Continuous Delivery / Deployment (CD)
- Automated Testing
- Configuration Management
- Policy as Code
- Continuous Monitoring

Examples of supporting technologies include Terraform, Ansible, GitHub Actions, Azure DevOps, GitLab CI/CD, and Jenkins.

The selection of tools remains an organisational decision and should align with enterprise standards.

---

# Relationship to ENAF

ENAF does not replace existing frameworks.

Instead, it provides the enterprise transformation lifecycle that integrates them into a single governed approach.

Typical alignment includes:

| ENAF Activity | Supporting Frameworks |
|--------------|-----------------------|
| Programme Delivery | MSP, PMI |
| Project Delivery | PRINCE2, PMBOK |
| Agile Delivery | Scrum, Kanban, SAFe |
| Enterprise Architecture | TOGAF, ArchiMate |
| Governance | COBIT, ISO/IEC 38500 |
| Service Transition | ITIL, ISO/IEC 20000 |
| Automation | DevOps and IaC practices |

---

# Summary

The Implementation stage brings together programme management, project management, Agile delivery, enterprise architecture, governance, service management, and automation into a single enterprise transformation model.

Rather than prescribing a specific methodology, ENAF provides the governance and architectural framework that enables organisations to integrate their preferred delivery approaches while maintaining alignment with strategic objectives, Enterprise Architecture, and business value.
